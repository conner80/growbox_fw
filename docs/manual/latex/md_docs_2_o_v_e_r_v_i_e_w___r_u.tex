\hypertarget{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md47}{}\doxysection{\texorpdfstring{1. Назначение}{1. Назначение}}\label{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md47}
Прошивка предназначена для автоматизации выращивания растений в гроубоксе (закрытом растениеводческом боксе). Система поддерживает заданные условия окружающей среды, управляя четырьмя исполнительными механизмами:


\begin{DoxyItemize}
\item {\bfseries{Лампа}} — освещение по расписанию (период активности в течение суток);
\item {\bfseries{Насос}} — полив по показаниям датчиков влажности почвы;
\item {\bfseries{Вентилятор}} — проветривание по температуре и влажности воздуха;
\item {\bfseries{Увлажнитель воздуха}} — поддержание влажности воздуха.
\end{DoxyItemize}

Управление и мониторинг выполняются со смартфона (или иного мастер-\/устройства) по \doxylink{class_bluetooth}{Bluetooth} через двоичный протокол команд. Настройки хранятся в энергонезависимой памяти EEPROM и сохраняются между перезапусками.

\hypertarget{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md59}{}\doxysection{\texorpdfstring{5. Стартовая инициализация}{5. Стартовая инициализация}}\label{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md59}
Конструктор {\ttfamily \doxylink{class_controller}{Controller}} ({\ttfamily \doxylink{controller_8cpp}{lib/\+controller/\+controller.\+cpp}}) выполняет инициализацию последовательно, собирая {\bfseries{битовую маску доступных устройств}} {\ttfamily device\+\_\+mask} (см. раздел 8):


\begin{DoxyEnumerate}
\item Создаётся \doxylink{class_r_t_c}{RTC}; если модуль ответил ({\ttfamily begin()}), устанавливается бит {\ttfamily \doxylink{controller_8h_aec15f51271494c6268bbe9ace3334e7c}{SENS\+\_\+\+RTC}}.
\item Создаётся объект хранилища {\ttfamily \doxylink{class_storage}{Storage}}; бит {\ttfamily \doxylink{controller_8h_a3cdfe4bb098c7f8f55bb1f9e96e83113}{SENS\+\_\+\+STORAGE}} устанавливается всегда (при успешной проверке размеров памяти).
\item По условной компиляции ({\ttfamily \#ifdef \doxylink{hal_8h_a2f504be032367b69f0a326e994a64ca0}{AIR\+\_\+\+SENSOR\+\_\+\+PIN}}, {\ttfamily SOIL\+\_\+\+MOISTURE\+\_\+\+PIN1/\+2}, {\ttfamily ...\+\_\+\+RELAY\+\_\+\+PIN}) создаются датчики и реле. Датчики почвы считаются исправными, если текущее значение АЦП не ниже нижней калибровочной границы. Реле добавляются в маску безусловно.
\item Создаётся кнопка (при определённом {\ttfamily \doxylink{hal_8h_a4879a25d5237d80d7a49c8d6dc3702ce}{BT\+\_\+\+BUTTON\+\_\+\+PIN}}).
\item Создаётся объект {\ttfamily \doxylink{class_bluetooth}{Bluetooth}}, которому передаётся контекст (указатель на контроллер) и callback-\/обработчик принятых команд {\ttfamily Controller::\+on\+Receive}.
\item Вызывается {\ttfamily Read\+Config()} — загрузка конфигурации из EEPROM; при любой ошибке устанавливается конфигурация по умолчанию.
\item Bluetooth-\/модуль включается в конфигурационном (AT) режиме, в него записываются сохранённые имя и пароль из конфигурации, после чего модуль переводится в транспортный режим и остаётся включённым (он сам отключится по таймауту неактивности).
\end{DoxyEnumerate}

Bluetooth-\/конструктор при первом создании дополнительно запрашивает у HC-\/05 через AT-\/команды адрес, имя, версию прошивки и пароль; модуль считается инициализированным, если пароль прочитан (не равен 0).

\hypertarget{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md61}{}\doxysection{\texorpdfstring{6. Главный рабочий цикл}{6. Главный рабочий цикл}}\label{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md61}
Каждая итерация {\ttfamily \doxylink{main_8cpp_afe461d27b9c48d5921c00d521181f12f}{loop()}} вызывает {\ttfamily \doxylink{class_controller_ad920ca3bf8fc1d163c0cc482d7c6226d}{Controller::\+\+Process()}}, который выполняет шаги в следующем порядке:


\begin{DoxyEnumerate}
\item {\bfseries{{\ttfamily check\+Pump\+Running()}}} — аварийный контроль времени работы насоса: если насос работает дольше {\ttfamily Max\+Work\+Time} секунд, он принудительно отключается и фиксируется время паузы.
\item {\bfseries{{\ttfamily read\+Sensors()}}} — опрос датчиков, но не чаще одного раза в {\ttfamily \doxylink{controller_8cpp_a25dbd6fd7142c23a240fd9b0fdc07749}{CHECK\+\_\+\+SENSORS\+\_\+\+FREQ}} (1000 мс), с учётом паузы {\ttfamily \doxylink{hal_8h_ae3b7ba5223047a968f613599b5ed9e35}{AIR\+\_\+\+SENSOR\+\_\+\+OPERATION\+\_\+\+DELAY}} (2000 мс) датчика DHT. Опрашиваются \doxylink{class_r_t_c}{RTC}, датчики почвы и датчик воздуха; успешно прочитанные значения сохраняются в структуре текущих параметров {\ttfamily \doxylink{struct_params}{Params}}:
\begin{DoxyItemize}
\item {\ttfamily pars.\+Now} — текущее Unix-\/время;
\item {\ttfamily pars.\+Soil\+Sensor1/\+2} — влажность почвы в процентах (0–100);
\item {\ttfamily pars.\+Air\+Sensor} — температура (float) и влажность воздуха. Если ни один датчик не обновился, итерация завершается.
\end{DoxyItemize}
\item {\bfseries{Автоматика исполнительных механизмов}} — только в стандартном режиме и только для устройств, чьи датчики успешно прочитаны (см. раздел 9): {\ttfamily process\+Lamp()}, {\ttfamily process\+Fan()}, {\ttfamily process\+Pump()}, {\ttfamily process\+Humidifier()}.
\item {\bfseries{{\ttfamily check\+BTButton()}}} — если \doxylink{class_bluetooth}{Bluetooth} выключен и нажата кнопка (или кнопка не сконфигурирована), модуль включается в транспортном режиме.
\item {\bfseries{{\ttfamily bt-\/\texorpdfstring{$>$}{>}Process\+Commands()}}} — приём и обработка пакетов протокола \doxylink{class_bluetooth}{Bluetooth}: разбор пакета, вызов callback контроллера, отправка ответа (см. разделы 10–11).
\end{DoxyEnumerate}

Общие принципы для всех механизмов:


\begin{DoxyItemize}
\item Каждый механизм работает в {\bfseries{автоматическом}} ({\ttfamily Is\+Auto = true}) или {\bfseries{ручном}} режиме. В ручном режиме автоматика не управляет устройством; его состояние задаётся командой {\ttfamily \doxylink{commands_8h_a8ddab075ebf1c378815abb74577783ed}{CMD\+\_\+\+SET\+\_\+\+STATUS}}.
\item Для каждого устройства задаётся {\bfseries{период активности}} (часы:минуты начала и конца). Проверка выполняется функцией {\ttfamily \doxylink{datetime_8h_ab195dafc45c7d235f40326912a0e6010}{Is\+Time\+In\+Range()}} ({\ttfamily \doxylink{datetime_8h}{include/\+common/\+datetime.\+h}}), которая корректно обрабатывает интервалы, переходящие через полночь. Если период некорректен (значения вне диапазонов либо начало равно концу), функция {\ttfamily \doxylink{config_8h_ae40863a9a6c0a1e5afe69c854ebd6009}{Is\+Always\+Activity()}} трактует его как «устройство активно круглосуточно», и управление опирается только на датчики.
\item Если датчик, участвующий в логике устройства, не инициализирован или не прочитан, соответствующее условие считается выполненным (устройство управляется остальными доступными критериями).
\end{DoxyItemize}\hypertarget{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md78}{}\doxysubsection{\texorpdfstring{9.\+1. Лампа}{9.\+1. Лампа}}\label{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md78}
Работает только по времени суток (период активности), датчики не используются. Текущее время внутри периода → лампа включена, вне периода → выключена.\hypertarget{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md79}{}\doxysubsection{\texorpdfstring{9.\+2. Вентилятор}{9.\+2. Вентилятор}}\label{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md79}
Условие по времени (период активности) {\bfseries{И}} условие по воздуху с гистерезисом:


\begin{DoxyItemize}
\item включение: влажность воздуха ≥ {\ttfamily Hum\+Start\+Vent} {\bfseries{или}} температура ≥ {\ttfamily Temp\+Start\+Vent};
\item выключение: влажность ≤ {\ttfamily Hum\+End\+Vent} {\bfseries{и}} температура ≤ {\ttfamily Temp\+End\+Vent};
\item между порогами (ни одно условие не выполнено) флаг остаётся «включить» — вентилятор работает.
\end{DoxyItemize}

Значения по умолчанию: включение при 24,0 °C или 70 \%, выключение при 20,0 °C и 50 \%.\hypertarget{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md80}{}\doxysubsection{\texorpdfstring{9.\+3. Насос (полив)}{9.\+3. Насос (полив)}}\label{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md80}
Условие по времени (период активности) {\bfseries{И}} условие по почве с гистерезисом:


\begin{DoxyItemize}
\item каждый активный датчик почвы запрашивает полив при влажности ≤ {\ttfamily Start\+Watering} (по умолчанию 30 \%) и считается удовлетворённым при влажности ≥ {\ttfamily End\+Watering} (по умолчанию 60 \%); между порогами сохраняется текущее состояние (гистерезис);
\item насос включается, когда все активные датчики запрашивают полив, и выключается, как только хотя бы один датчик удовлетворён;
\item неактивный датчик условию не препятствует.
\end{DoxyItemize}

Дополнительные ограничения на запуск и работу:


\begin{DoxyItemize}
\item {\bfseries{{\ttfamily Pause\+Between\+Start}}} (по умолчанию 600 с) — минимальная пауза между запусками насоса; {\bfseries{0}} — без ограничения;
\item {\bfseries{{\ttfamily Freq\+Watering}}} (по умолчанию 72 ч) — максимальная частота полива: насос не запускается чаще одного раза в указанное число часов; {\bfseries{0}} — без ограничения. Перед запуском проверяются оба интервала — действует больший;
\item {\bfseries{{\ttfamily Max\+Work\+Time}}} (по умолчанию 300 с) — максимальное непрерывное время работы, контролируется {\ttfamily check\+Pump\+Running()} независимо от способа включения; {\bfseries{0}} — без ограничения (остановка только по условиям или команде).
\end{DoxyItemize}

Момент последнего запуска фиксируется и используется для контроля всех трёх ограничений, поэтому принудительный запуск через {\ttfamily Activate\+Devices()} учитывается автоматикой так же, как собственный.\hypertarget{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md81}{}\doxysubsection{\texorpdfstring{9.\+4. Увлажнитель воздуха}{9.\+4. Увлажнитель воздуха}}\label{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md81}
Условие по времени (период активности) {\bfseries{И}} влажность воздуха с гистерезисом:


\begin{DoxyItemize}
\item включение: влажность ≤ {\ttfamily Hum\+Start\+Hum} (по умолчанию 30 \%);
\item выключение: влажность ≥ {\ttfamily Hum\+End\+Hum} (по умолчанию 40 \%);
\item между порогами (ни одно условие не выполнено) флаг остаётся «включить» — увлажнитель работает.
\end{DoxyItemize}

EEPROM AT24\+C256 имеет ограниченный ресурс записи (обычно \texorpdfstring{$\sim$}{\string~}10⁵ циклов на ячейку), поэтому запись организована циклически ({\ttfamily \doxylink{storage_8cpp}{lib/\+hal/\+storage.\+cpp}}):


\begin{DoxyItemize}
\item Память делится на {\bfseries{слоты}} размером 128 байт (структура {\ttfamily \doxylink{struct_data_slice}{Data\+Slice}} размером 97 байт выравнивается вверх до границы 32 байт): слот = байт статуса, 4-\/байтный счётчик записей и сама конфигурация (92 байта). Всего 256 слотов.
\item Каждая запись помещает конфигурацию в {\bfseries{следующий}} слот со значением счётчика на единицу больше максимального, затем выполняется контрольное чтение (верификация). \item Перебор слотов {\bfseries{циклический}}: после последнего слота запись продолжается с начала памяти, перезаписывая самые старые данные.
\item При чтении просматриваются все слоты и выбирается активный с максимальным счётчиком записей, таким образом восстанавливается и номер текущего слота.
\end{DoxyItemize}

Благодаря этому запись при каждом изменении конфигурации попадает в новые ячейки, равномерно распределяя износ по всей памяти; ресурса EEPROM (порядка 10⁵ циклов записи на ячейку) хватает на десятилетия штатной эксплуатации.

\item Пакет запроса начинается с {\ttfamily 0x\+FE}, ответа — с {\ttfamily 0x\+EF}.

\item Ответ на команду отправляется с сигнатурой {\ttfamily 0x\+EF} и проходит проверку длины строго по формату команды; если мастер ответил {\ttfamily NACK}, ответ отправляется повторно.

Особенности выполнения команд:


\begin{DoxyItemize}
\item {\ttfamily \doxylink{commands_8h_a1b78ee87bf0c178fd14cb6c88a36d6f0}{CMD\+\_\+\+SET\+\_\+\+BT\+\_\+\+NAME}}/{\ttfamily \doxylink{commands_8h_a900bdf8a70cc1fee39ba4e5e29e20f5f}{CMD\+\_\+\+SET\+\_\+\+BT\+\_\+\+PASS}}: устройство само переводит модуль в AT-\/режим, выполняет команду, возвращает транспортный режим; ответ содержит код результата (0x00 — успех, 0x01 — некорректные данные, 0x02 — не удалось переключить режим, 0x03 — аппаратная ошибка).
\item {\ttfamily \doxylink{commands_8h_a8ddab075ebf1c378815abb74577783ed}{CMD\+\_\+\+SET\+\_\+\+STATUS}} принимает последовательность блоков «идентификатор устройства + данные»; значения вне допустимых диапазонов отклоняются с указанием проблемных устройств в маске ошибок; невалидные поля периода активности интерпретируются как «круглосуточная активность».
\item Ответ {\ttfamily \doxylink{commands_8h_a66f7b6f26a4f3c2ff469ccf6ae05c44a}{CMD\+\_\+\+GET\+\_\+\+STATUS}} собирается из блоков только тех устройств, которые есть и в запрошенной маске, и в маске инициализированных; в полях периода активности значение 100 означает «период не задан/\+некорректен» (круглосуточная активность).
\end{DoxyItemize}

\hypertarget{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md92}{}\doxysection{\texorpdfstring{12. Режимы работы устройства}{12. Режимы работы устройства}}\label{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md92}
Устройство работает в одном из двух режимов ({\ttfamily Controller::\+is\+Std\+Mode}):


\begin{DoxyItemize}
\item {\bfseries{Стандартный режим (0x01)}} — штатная работа: автоматика по разделу 9 активна.
\item {\bfseries{Режим калибровки (0x00)}} — автоматика отключена; при входе в режим все исполнительные механизмы принудительно отключаются ({\ttfamily Activate\+Devices(0x0000)}). Предназначен для калибровки датчиков и безопасного изменения настроек.
\end{DoxyItemize}

Режим переключается командой {\ttfamily \doxylink{commands_8h_ab08c18e4b6ea58665d8743bd47182946}{CMD\+\_\+\+SET\+\_\+\+MODE}}, текущее значение возвращается {\ttfamily \doxylink{commands_8h_ad37107a45db89a0aa7f06dfbf096d917}{CMD\+\_\+\+GET\+\_\+\+MODE}} (а также битом в ответе {\ttfamily \doxylink{commands_8h_a42bf1fd637b1c921700bf479cc2f8533}{CMD\+\_\+\+INFO}}). Состояние режима не сохраняется в EEPROM и после перезагрузки всегда стандартный.

\hypertarget{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md94}{}\doxysection{\texorpdfstring{13. Замечания и ограничения текущей реализации}{13. Замечания и ограничения текущей реализации}}\label{md_docs_2_o_v_e_r_v_i_e_w___r_u_autotoc_md94}
Замечания, зафиксированные в предыдущей редакции документа (незадействованные параметры насоса и почвы, немедленное отключение насоса при {\ttfamily Max\+Work\+Time = 0}, неработающие команды смены пароля/\+времени/\+имени по \doxylink{class_bluetooth}{Bluetooth}, запись настроек насоса и обоих датчиков почвы в {\ttfamily \doxylink{commands_8h_a8ddab075ebf1c378815abb74577783ed}{CMD\+\_\+\+SET\+\_\+\+STATUS}}, опечатка в {\ttfamily process\+Humidifier()}, бесконечный перебор слотов EEPROM, переполнение буфера имени \doxylink{class_bluetooth}{Bluetooth} и условие в {\ttfamily \doxylink{commands_8h_ab08c18e4b6ea58665d8743bd47182946}{CMD\+\_\+\+SET\+\_\+\+MODE}}), устранены в коде. Актуальные ограничения:


\begin{DoxyEnumerate}
\item {\bfseries{Имя \doxylink{class_bluetooth}{Bluetooth}.}} Протокол допускает имя до 32 символов, а имя, применяемое при старте, хранится в конфигурации в поле на 20 символов: имя, заданное командой {\ttfamily \doxylink{commands_8h_a1b78ee87bf0c178fd14cb6c88a36d6f0}{CMD\+\_\+\+SET\+\_\+\+BT\+\_\+\+NAME}} без изменения конфигурации, после перезагрузки будет сброшено к конфигурационному значению.
\item {\bfseries{Частота опроса датчика воздуха}} принудительно ограничена паузой 2 с; неверные значения (вне 0–100 \%) отбрасываются с кодом ошибки.
\item {\bfseries{Инициализация \doxylink{class_bluetooth}{Bluetooth}.}} Модуль считается инициализированным, если удалось прочитать ненулевой пароль; сбой опроса параметров на старте отражается на работе транспорта до перезагрузки.
\item {\bfseries{Пороги почвы.}} По протоколу требуется {\ttfamily Start\+Watering \texorpdfstring{$<$}{<} End\+Watering} — блок настроек с нарушением порядка порогов отклоняется с кодом 0x02. Ранее записанные в EEPROM конфигурации с некорректными порогами читаются, но работают как обычный порог включения без гистерезиса.
\end{DoxyEnumerate}
